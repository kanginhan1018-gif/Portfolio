# 분지 점수 함수 비교 실험 설계

날짜: 2026-10-22 · 코드: `/Users/inhan/Developer/branching-score-experiment`

## 1. 질문

분지 규칙에서 두 자식 노드의 LP 하한 증가량 $(\Delta^-,\Delta^+)$ 를 하나의 점수로 합치는 방식이 풀이 시간과 트리 크기에 영향을 주는가?

배경은 다음과 같다.
- Achterberg–Koch–Martin(2005)은 가중합 $(1-\mu)\min+\mu\max$, $\mu=1/6$ 을 쓴다(전문 확인).
- SCIP의 기본값은 곱(`branching/scorefunc = p`)이다. SCIP 소스 `branch.c` 의 `SCIPbranchGetScore` 와 파라미터 문서로 확인했다. 곱이 가중합보다 10% 넘게 낫다는 Achterberg의 결과는 Anderson–Le Bodic–Morgan(arXiv 1909.01472)이 인용한 것을 읽었고, 원 학위논문은 읽지 못했다.
- 같은 arXiv 논문은 Le Bodic–Nemhauser의 ratio, svts 점수가 SCIP 6.0 기준 MIPLIB 2017 benchmark 전체에서 시간 1% 안팎(ratio 1.01배, svts 0.99배)이고, 10,000 노드 이상 인스턴스에서 svts 7%(ratio 1%), 50,000 노드 이상에서 svts 11%(ratio 4%) 빠르다고 보고한다. 이 두 점수는 SCIP 10.0 파라미터에는 없어서 이번 실험 대상이 아니다.

**가설 H1**: 곱(SCIP 기본)은 가중합 $\mu=1/6$ (2005년 논문 설정)보다 노드 수가 적다.
**가설 H2**: 단순 합($\mu=1/2$)은 한쪽 증가량이 극단적인 후보를 과대평가해서 곱보다 나쁘다.
**가설 H3**: 몫 $\min^2/\max$ 은 곱과 비슷한 순위를 낸다.
**탐색적 H4** (사용자 아이디어): 방향별 최대 증가량으로 나눈 비율의 합(`normsum`)은 단순 합과 곱 사이에 있다. 출판된 규칙이 아니며, 정의는 코드 주석에 있다.

가설은 실험 전에 고정한 것이고, 결과가 달라도 그대로 보고한다.

## 2. 비교 대상

| 이름 | 단계 | 정의 |
|---|---|---|
| `product` | 1 | `branching/scorefunc=p` (SCIP 기본, 기준선) |
| `wsum_1_6` | 1 | `s`, `scorefac=1/6` (2005년 논문과 같은 형태) |
| `sum_1_2` | 1 | `s`, `scorefac=0.5` (단순 합의 상수배) |
| `quotient` | 1 | `q`, $\min^2/\max$ |
| `c_*` | 2 | 후보 10개를 strong branching 으로 평가하고 점수는 코드에서 직접 계산 (`c_normsum` 포함) |

1단계는 SCIP의 reliability pseudocost 분지(relpscost)를 그대로 쓰고 점수 파라미터만 바꾼다. 2단계는 pseudocost 추정 오차를 빼고 점수 함수 효과만 보기 위한 것이다.

## 3. 인스턴스와 절차

- 모집단: MIPLIB 2017 benchmark set 240개(Gleixner 외, 2021).
- 단계 0 (보정): 기본 설정으로 300초 제한, 시드 0. 푼 것 중 10초 이상 300초 이하이고 노드 1,000개 이상인 인스턴스만 남긴다. 쉬운 문제와 너무 어려운 문제를 거르는 목적이다. 선택 기준은 기본 설정만으로 정해서 비교 대상에 유리하지 않게 했다.
- 본 실험: 시간 제한 600초, 시드 3개(`randomization/permutationseed` 와 `randomseedshift`), 단일 스레드.
- 하위 분석: 어느 설정에서든 10,000 노드 이상이 필요한 "어려운" 인스턴스만 따로 본다(Anderson 외와 같은 방식).

## 4. 지표

- 푼 횟수(solved/runs).
- 시간과 노드 수의 shifted geometric mean (시간 shift 10, 노드 shift 100). 못 푼 실행은 시간 제한 값으로 계산한다.
- 인스턴스별로 시드의 기하평균을 먼저 낸 뒤 설정 간 비교한다. 기준선 대비 비율도 같이 낸다.

## 5. 타당성 위협과 대응

| 위협 | 대응 |
|---|---|
| 동시 실행이 시간을 흔든다 | 워커 수를 코어 수−1 이하로 제한하고, 노드 수를 함께 본다 |
| 시드 분산 | 시드 3개, 인스턴스 단위로 묶어 비교 |
| `scorefunc` 가 relpscost 외 다른 곳에도 쓰인다 | 1단계는 "SCIP 전체 설정 효과"로 해석하고, 2단계에서 점수 효과만 분리 |
| 인스턴스 선택 편향 | 기준선 설정만으로 선택, 선택 목록을 결과와 함께 저장 |
| 결과의 일반화 | SCIP 10.0 한 솔버, 한 인스턴스 세트의 결과로만 해석 |

## 6. 비용 추정

선택된 인스턴스가 60개라고 가정하면, 1단계는 60 × 4 × 3 = 720회, 최악 600초씩 약 120 CPU 시간이다. 워커 3개면 약 40시간까지 갈 수 있으니 처음에는 인스턴스 20개 × 시드 1개로 파일럿을 돌려 시간을 재고 규모를 정한다.
