# WordGarden: 검색한 단어를 복습과 퀴즈로 연결하는 학습 앱

> 게시 검토용 본문 초안. 사이트 반영·배포 전 검토본입니다.

**단어를 찾은 뒤 별도로 정리하지 않아도, 검색 기록이 그날의 복습 문장과 퀴즈로 이어지는 개인용 웹앱을 만들었습니다.**

| 항목 | 내용 |
|---|---|
| 분야 | 개인용 학습 제품·AI 기능·웹앱 |
| 담당 | 학습 흐름과 데이터 모델, 사전 연결, 복습 생성·검증, 퀴즈, 저장·이전·접근 제어 |
| 도구 | Python, SQLite, JavaScript, 로컬 Codex CLI, 클라우드 Worker·R2 |
| 주요 산출물 | 로컬 앱, 개인용 클라우드 앱, 생성 작업 브리지, 데이터 이전과 테스트 코드 |

## 검색 기록을 학습 자료로 남기는 문제

영어를 공부하면서 표현을 검색해도, 나중에 다시 보려면 단어장에 옮기고 예문을 만들고 복습 문제를 준비해야 합니다. 검색과 정리가 다른 작업이면 기록이 흩어지거나 복습이 미뤄질 수 있습니다.

WordGarden은 사용자가 실제로 찾은 표현을 날짜별로 저장하고, 그 표현을 이용한 복습 문장과 객관식 퀴즈를 제공합니다. 저는 사전 검색부터 기록·복습·퀴즈, 로컬 저장과 개인 클라우드 이전까지 연결했습니다. 사용자가 단어를 다시 입력하는 단계를 줄이는 제품 흐름에 초점을 뒀습니다.

## 하나의 검색에서 이어지는 학습 흐름

| 사용자 행동 | 앱의 처리 |
|---|---|
| 단어·숙어 검색 | 영어 설명·한국어 뜻·예문·출처를 조회하고 날짜별 기록 저장 |
| 같은 날 다시 검색 | 기존 기록의 검색 횟수 갱신 |
| 다른 날 다시 검색 | 해당 날짜의 새로운 학습 기록 생성 |
| 복습 요청 | 그날의 표현으로 영어 문장·한국어 해석 생성 |
| 퀴즈 시작 | 저장된 사전 뜻을 이용해 양방향 객관식 문제 구성 |
| 기록 삭제·내보내기 | 날짜별 학습 자료와 복습 대상에 반영, JSON 내보내기 |

단어 자체와 특정 날짜에 그 단어를 찾은 사건을 구분했습니다. 그래야 같은 표현을 어느 날 다시 찾았는지 남길 수 있고, 한 날짜의 기록을 지워도 다른 날짜의 학습 자료까지 사라지지 않습니다.

## 사전 조회 실패와 뜻이 없는 상태를 구분했다

영어와 한국어 사전은 별개의 항목이므로 뜻이 일대일로 대응한다고 가정하지 않았습니다. 한쪽 뜻이 없으면 그 상태를 표시하고, 사전 연결에 실패한 경우에는 없는 단어라고 단정하지 않도록 했습니다. 복수 뜻과 예문, 원문 링크와 출처를 함께 보존합니다.

뜻을 AI가 대신 채우도록 만들기보다 사전 자료를 학습의 기준으로 두었습니다. 복습 문장은 생성형 AI가 만들고, 퀴즈는 저장된 사전 기록을 이용하는 식으로 기능의 근거를 나눴습니다.

## AI 생성 결과는 저장 전에 검사했다

복습 생성은 그날 학습한 표현을 로컬 Codex CLI에 전달하는 방식입니다. 결과가 반환되면 문장·해석·사용 표현의 JSON 구조와 문자열을 확인하고, 학습 표현이 실제 영어 문장에 포함됐는지 검사합니다. 표현 목록에만 단어를 적고 정작 문장에서 빠뜨린 응답은 성공으로 저장하지 않습니다.

같은 단어 목록으로 이미 만든 복습은 재사용하고, 새로운 표현이 추가되면 기존 결과가 오래됐다는 상태로 표시합니다. 중복 생성 요청을 제어하고, 재생성에 실패하면 이전에 저장한 정상 문장을 유지합니다. 이 구조로 생성 작업의 성공·실패와 학습 기록의 보존을 분리했습니다.

이 검사는 형식과 표현 포함 여부를 확인합니다. 문법·번역·학습 난이도의 정확성을 모두 자동 보증하는 평가는 아니므로 생성 문장의 교육적 품질은 별도 검증이 필요합니다.

## 퀴즈의 오답이 정답과 겹치지 않게 했다

퀴즈는 영어에서 한국어 뜻을 찾는 방향과 한국어 뜻에서 영어를 찾는 방향을 제공합니다. 출제할 수 있는 표현이 2개 이상일 때 시작하고 보기는 최대 4개로 구성했습니다. 의미를 정리해 비교한 뒤 뜻이 겹치는 선택지를 오답으로 넣지 않으며, 한국어 뜻이 없는 표현은 해당 퀴즈에서 제외합니다.

보기의 겉모양을 달리하는 것보다 사용자가 모호한 문제로 잘못 채점되지 않는 것이 중요하다고 봤습니다. 발음은 브라우저·운영체제가 제공하는 음성을 이용해, 학습 기록과 함께 확인할 수 있도록 했습니다.

## 로컬 기록을 개인용 클라우드로 옮겼다

처음에는 Python 서버와 SQLite를 이용하는 로컬 앱으로 구현했습니다. 이후 여러 기기에서 같은 기록을 보도록 단어장과 복습 결과를 개인 계정만 접근하는 Worker·R2 저장소로 옮겼습니다. 클라우드에 생성 API를 직접 붙이는 대신 기존 로컬 생성 작업을 브리지로 연결했습니다.

| 구성 요소 | 역할 |
|---|---|
| 브라우저 | 검색·기록·복습·퀴즈 화면 |
| 클라우드 Worker | 요청 처리, 사용자·작업 경로 구분, 데이터 검증 |
| R2 저장소 | 개인 단어장·복습 결과 저장, 조건부 쓰기로 갱신 충돌 처리 |
| 로컬 브리지 | 생성 작업 요청 확인, Codex 실행, 결과·실패 상태 전송 |
| 기존 SQLite | 이전할 로컬 자료의 원본 보존 |

브리지에는 작업 ID를 함께 보내고 만료된 작업의 결과를 정상 결과로 덮어쓰지 않도록 처리했습니다. 실제 이전 기록은 로컬 어휘 4개이며, 대규모 사용자 데이터 이전 성과로 표현하지 않습니다. 익명 요청 차단과 원본 보존이 문서에 남아 있습니다. 개인 단어장과 비공개 서비스 접속 정보는 포트폴리오에서 제외합니다.

## 어떤 동작을 검증했나

| 검증 대상 | 코드·테스트에서 다룬 조건 |
|---|---|
| 기록 지속성 | 같은 날·다른 날 재검색, 앱 재시작 후 보존 |
| 삭제 범위 | 특정 날짜 기록 삭제, 다른 날짜 기록 유지, 복습의 오래됨 표시 |
| 사전 상태 | 한국어 뜻 누락, 여러 뜻·예문, 일부 사전 연결 실패 |
| 생성 제어 | 중복 요청, 새 표현 추가, 누락된 표현, 잘못된 응답 |
| 실패 복구 | 생성 실패 후 기존 복습 문장 유지 |
| 접근·저장 | 요청 경로 구분, 클라우드 조건부 쓰기와 브리지 작업 결과 처리 |

표는 기존 구현과 테스트가 다루는 범위입니다. 이번 포트폴리오 보완 작업에서 운영 서비스와 외부 사전을 다시 호출하거나 실제 브라우저의 전체 동작을 재검증한 결과는 아닙니다.

## 제품을 만들며 내린 판단

검색·기록·복습을 하나의 흐름으로 연결하되, 외부 사전이나 생성 도구의 실패 때문에 이미 남긴 학습 자료가 사라지지 않게 했습니다. 기록을 저장하는 위치와 문장을 생성하는 위치가 달라도, 사용자가 현재 상태와 재시도 가능 여부를 알 수 있게 구성했습니다.

남은 제약도 있습니다. 브리지가 실행 중인 컴퓨터가 있어야 복습을 생성할 수 있고 구독 사용 한도를 소비합니다. 사용자 수나 학습 효율의 개선은 측정하지 않았습니다. 다음 검증은 실제 학습에서 기록·복습 기능을 얼마나 지속적으로 사용하는지, 생성 문장의 정확성과 난이도가 적절한지 관찰하는 것입니다.
