## 읽기 작업의 문제와 제품 범위

논문을 읽으면서 모르는 문장을 질문하고, 답변의 근거를 확인하고, 이해한 내용을 노트로 남기는 과정을 하나의 로컬 작업 공간에 연결했습니다. PDF 업로드와 개요, 서재, 제목·DOI·arXiv 검색, 공식 서지 확인과 Zotero 저장을 구성하고, PPT와 원문을 함께 보며 학습할 수 있게 확장했습니다. 단순한 PDF 채팅보다 읽기 흐름과 원문 연결을 유지하는 데 초점을 뒀습니다.

## 근거 검색과 답변 길이

답변에는 선택한 글뿐 아니라 본문 문단과 정의 문장을 검색해 사용합니다. 번역에서는 불필요한 본문을 보내지 않고, 설명에서는 근거 문맥을 더 쓰도록 입력을 나눴습니다. 기본 답변은 3줄·300자로 제한하고 필요할 때 설명과 근거 범위를 펼칩니다. 스캔본과 본문 검색 실패는 다른 상태로 표시하며, 수식·그림을 모두 이해하는 기능으로 과장하지 않았습니다.

## 원문 주석과 질문의 연결

후속 작업에서는 왼쪽 질문을 유지한 채 오른쪽의 PPT·PDF를 바꿀 수 있게 하고, 선택한 실제 인용문의 위치를 찾아 하이라이트와 문답 주석을 저장했습니다. 주석에는 질문 ID·메인 질문·작업 자료·물리적 PDF 페이지·버전을 연결했습니다. 여러 위치가 일치하면 사용자가 후보를 확인하게 하고, 원문이 바뀐 과거 주석을 새 PDF에 자동으로 겹쳐 그리지 않도록 했습니다. 주석은 앱 저장 자료이며 PDF 바이너리나 Zotero 네이티브 주석과의 왕복 동기화는 구현 범위 밖입니다.

## 학습 기록과 콘텐츠 내보내기

학습 기록에서는 직접 쓴 이해 내용과 AI 답변을 분리합니다. 세션 JSON·Markdown을 저장하고 Obsidian에는 기존 노트를 덮어쓰지 않고 추가합니다. 인스타 초안은 직접 메모가 충분한 경우에만 만들고, 형식·길이·수치 확인 후 이미지 렌더러로 넘기는 흐름을 마련했습니다. 콘텐츠 제작과 실제 SNS 게시를 분리했습니다.

## 실제 사용량 측정

사용량 측정도 진행했습니다. 두 논문·질문 10개의 로컬 비교에서 평균 출력 토큰은 334에서 219로 줄었고, 답에 “확인 못 함”이 포함된 건수는 5/10에서 3/10으로 바뀌었습니다. 후자는 정답률이 아닙니다. 약 20%의 비용 감소는 캐시 조건을 보정한 토큰 기반 환산 추정이며 실제 구독 청구액 절감으로 주장하지 않습니다. 작은 문맥부터 여러 차례 확장하는 시도가 오히려 호출량을 늘린 실패도 기록했습니다.

## 확인한 범위와 남은 연결

저장·검색·주석·임시 보관함과 UI 모의 검증 기록이 있지만, 실제 Claude 생성부터 사용자 Obsidian·Zotero·PDF 렌더링까지 모든 통합 경로를 같은 환경에서 확인한 것은 아닙니다. 일반 사용자 대상의 학습 시간 절감이나 답변 정확도도 아직 측정하지 않았습니다.
